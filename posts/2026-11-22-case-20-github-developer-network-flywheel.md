## 案例背景

代码托管工具并不稀缺，但 GitHub 把「代码托管」和「协作社交」结合起来：每个人有自己的主页、贡献记录和公开仓库，代码既是工作成果，也是个人履历。

## 核心困境

> 开发者对新工具极其挑剔、迁移成本高。你怎么让一个人愿意把工作搬过来，还能说服整个团队和社区一起用？

## 关键事实

- **入口**：免费公共仓库，个人开发者零成本使用
- **协作**：Pull Request、Issue、Star、Fork 把代码变成社交行为
- **沉淀**：公开贡献记录成为开发者的职业资产，越用越不愿迁移
- **结局**：2018 年被微软以约 75 亿美元收购（公开报道）

## 分析框架：开发者增长 × 网络效应飞轮

1. **个人入口**：免费账号让个人先成为用户，再由个人带着项目进入公司。
2. **协作即分发**：Fork、Star、PR 都发生在公开页面，每一次协作都是曝光。
3. **资产沉淀**：贡献记录、开源项目、声誉都留在平台，迁移意味着放弃资产。
4. **飞轮**：开发者多 → 开源项目多 → 平台更有价值 → 吸引更多开发者。

## 当时的决策与执行

1. 免费公共仓库降低个人门槛，把开发者账号做成职业身份。
2. 把协作动作产品化（PR、Issue、Star），让社交行为自然发生。
3. 让开源项目在平台上沉淀，形成难以迁移的公共资产。

## 结果

成为全球开发者的基础设施，2018 年被微软以约 75 亿美元收购（公开报道）。

## 课堂讨论题

1. 为什么开发者社区是最难复制的护城河？
2. 免费公共仓库如何变现？免费和付费的边界在哪里？
3. 你自己的内容或工具，能否用类似的「个人资产沉淀」思路做增长？

## 迁移到出海场景

这个案例和你正在做的事直接相关：一个公开、可检索、能被别人复用的知识库，本身就是增长入口。可照做的动作：把你的出海干货持续用 Markdown 沉淀在公开仓库里，每篇文章有稳定地址、作者署名、可转载授权；把工具、模板、清单也放进去。别人引用、转发、二次创作时，都是在替你分发。对个人品牌而言，「公开贡献记录」和 GitHub 上的绿格子是同一种资产。

## 别踩的坑

> 社区增长极慢，早期没有网络效应时，产品体验必须自己站得住。另外，开发者对商业化非常敏感，付费边界处理不当会引发社区反弹。

## 一句话结论

**让用户的贡献变成资产，他就不会走。**
